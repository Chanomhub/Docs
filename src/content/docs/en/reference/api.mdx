This guide outlines the public and developer APIs provided by the **ChanomHub** platform for querying, integrating, and managing articles, mods, downloads, and developer features.

## Overview

- **Base URL (REST)**: `https://api.chanomhub.com/api` (or `http://localhost:3000/api` for local development)
- **GraphQL endpoints**: `/api/graphql` (v1), `/api/v2/graphql`, `/api/v3/graphql`
- **Interactive Swagger docs**: [https://api.chanomhub.com/api-docs](https://api.chanomhub.com/api-docs)

All REST responses are wrapped by a global envelope: the payload you want is inside the `data` field of the response body.

```json
{ "data": { "...payload": "" }, "statusCode": 200, "timestamp": "2026-01-01T00:00:00.000Z" }
```

The examples below show the unwrapped payload shape.

## 1. Authentication

Public read endpoints (articles, mods, downloads, search) work without a token. For write operations and personal resources, send a Bearer token:

```http
Authorization: Bearer <YOUR_TOKEN>
```

### Session endpoints (Better Auth)

| Endpoint | Method | Description |
|---|---|---|
| `/api/auth/sign-in/email` | `POST` | Sign in with email and password |
| `/api/auth/sign-up/email` | `POST` | Register a new account |
| `/api/auth/sign-out` | `POST` | Sign out / invalidate the session |
| `/api/auth/sign-in/social` | `GET` | Start OAuth login (`google`, `discord`, `github`); `provider` query parameter required |

### Token & password endpoints (JWT)

| Endpoint | Method | Auth | Description |
|---|---|---|---|
| `/api/auth/refresh` | `POST` | ❌ | Refresh an access token |
| `/api/auth/forgot-password` | `POST` | ❌ | Send a password reset email |
| `/api/auth/reset-password` | `POST` | ❌ | Reset the password with a reset token |
| `/api/auth/logout` | `POST` | ✅ | Revoke the current token |
| `/api/auth/logout-all` | `POST` | ✅ | Revoke all tokens of the user |
| `/api/auth/exchange` | `POST` | ❌ | Exchange a third-party token for a ChanomHub JWT |
| `/api/auth/verify` | `GET` / `POST` | ❌ | Validate a JWT; returns `{ valid, userId }` |

## 2. Articles API

### 2.1 List articles

`GET /api/articles`

**Query parameters:**

- `q` (string): search in title/description/body (minimum 3 characters)
- `author`, `creator`, `tag`, `category`, `platform`, `engine`, `language`, `favorited` (string): filters
- `status` (string): `PUBLISHED` by default for anonymous calls
- `sequentialCode` (string): exact article code lookup
- `sortBy` (string): `updatedAt` (default), `createdAt`, `viewsCount`, `title`
- `sortOrder` (string): `asc` / `desc`
- `limit` (number, default `20`), `offset` (number, default `0`) — pagination is offset-based

<Tabs>
  <TabItem label="cURL">
```bash
curl "https://api.chanomhub.com/api/articles?limit=10&offset=0&q=renpy"
```

  </TabItem>
</Tabs>

**Response (unwrapped):**

```json
{
  "articles": [ { "id": 941, "title": "...", "slug": "...", "ver": "1.2.0", "engine": "RENPY", "...": "" } ],
  "articlesCount": 853
}
```

### 2.2 Feeds & own articles (authenticated)

- `GET /api/articles/feed` — articles from followed users
- `GET /api/articles/me` — the caller's own articles (including drafts)
- `POST /api/articles/reserve` — reserve a unique slug for a new article

### 2.3 Article details

- `GET /api/articles/:slug` — full article by slug
- `GET /api/articles/:slug/related` — related articles
- `POST /api/articles/:slug/view` — increment the view counter

### 2.4 Article management (authenticated)

- `POST /api/articles` — create an article (draft)
- `PUT /api/articles/:slug` — update an article
- `DELETE /api/articles/:slug` — soft-delete (restore with `POST /api/articles/:slug/restore`)
- `DELETE /api/articles/:slug/permanent` — permanent delete
- `POST /api/articles/:slug/publish-request` — submit a draft for moderation
- `POST /api/articles/:slug/transfer-request` — request ownership transfer to another user
- `GET /api/articles/:slug/transfer-request` — get the active transfer request
- `DELETE /api/articles/:slug/transfer-request` — cancel the transfer request
- `POST /api/articles/:slug/favorite` — bookmark an article
- `DELETE /api/articles/:slug/favorite` — remove the bookmark
- `POST /api/articles/:slug/rate` — rate an article (`{ "rating": 1..10 }`)

### 2.5 Revision history

- `GET /api/articles/:slug/revisions` — list revisions
- `GET /api/articles/:slug/revisions/:version` — one revision (with reconstructed content)
- `POST /api/articles/:slug/revisions/:version/restore` — restore a revision
- `GET /api/articles/:slug/revisions/compare` — diff two revisions (`from`, `to` query parameters)

## 4. Mods & Engines API

Mods are translation/gameplay add-ons attached to published articles.

- `GET /api/mods` — list mods; filters: `status` (moderators only), `skip`, `take`, `type`, `language`, `search`, `articleId`, `articleSlug`, `creatorId`
- `GET /api/mods/article/:slug` — all mods of an article (filters: `status`, `type`, `language`)
- `GET /api/mods/:slug/versions` — version history of a mod
- `GET /api/mods/:slug/versions/:version` — one mod version
- `GET /api/mods/:slug/download/:version` — download a specific version
- `POST /api/mods/article/:slug` (Auth) — submit a mod (files a moderation request automatically)
- `POST /api/mods/article/:slug/nst-submission` (Auth) — submit an NST translation package
- `POST /api/mods/:id/versions` (Auth) — publish a new mod version
- `PATCH /api/mods/:id/versions/:versionId` (Auth) — edit a mod version
- `DELETE /api/mods/:id/versions/:versionId` (Auth) — remove a mod version
- `PATCH /api/mods/:id` (Auth) — update mod metadata
- `PATCH /api/mods/:id/status` (Auth, moderators) — approve/reject a mod
- `DELETE /api/mods/:id` (Auth) — delete a mod

Taxonomy:

- `GET /api/mod-categories` — mod categories
- `GET /api/engines` — supported game engines (Ren'Py, Unity, RPG Maker, …)

## 5. Downloads API

- `GET /api/downloads/article/:articleId` — **public** list of approved download links for an article: `{ links: [{ url, isActive, status, ... }] }`
- `GET /api/downloads/article/slug/:slug` — same, by slug
- `GET /api/downloads/:id` (Auth) — one download link by ID
- `POST /api/downloads` (Auth) — create a download link
- `PATCH /api/downloads/:id` (Auth) — update a download link
- `DELETE /api/downloads/:id` (Auth) — delete a download link
- `GET /api/downloads` (Auth) — list your download links
- `GET /api/downloads/pending` (Auth, moderators) — links awaiting moderation
- `PATCH /api/downloads/:id/moderate` (Auth, moderators) — approve/reject a link

Official download sources (verified mirrors):

- `GET /api/official-download-sources/article/:articleId/approved` — approved official sources of an article

## 12. MCP Server (Model Context Protocol)

ChanomHub exposes a read-only [MCP](https://modelcontextprotocol.io) server over Streamable HTTP for AI assistants:

- `POST /api/mcp` (Auth) — JSON-RPC transport (`initialize` first, then session requests carry the `mcp-session-id` header)
- `GET /api/mcp` (Auth) — SSE stream for an existing session
- `DELETE /api/mcp` (Auth) — terminate the session

Exposed tools are read-only queries over articles, mods, comments, and profiles.

## 13. GraphQL API

Three GraphQL versions are served by the same gateway (GraphQL Yoga):

| Version | Endpoint | Notes |
|---|---|---|
| v1 | `/api/graphql` (alias `/api/v1/graphql`) | Original schema |
| v2 | `/api/v2/graphql` | Current public schema (`public`, `system`, `moderate` root queries) |
| v3 | `/api/v3/graphql` | Same schema as v2; also accepts the HTTP `QUERY` method (mutations rejected on `QUERY`) |

- **Methods**: `GET` (cached 60s) and `POST`; `QUERY` on v3
- **Introspection is disabled in production** (per-environment override: `ENABLE_INTROSPECTION=true`)
- Query depth is limited to 10
- Automatic persistent queries (APQ) are supported

Browse the schema in the [GraphQL Schema Browser](/en/reference/graphql-schema/) (built from a committed snapshot).

Example:

```bash
curl https://api.chanomhub.com/api/v2/graphql \
  -H 'Content-Type: application/json' \
  --data '{"query":"{ public { articles(limit: 5) { id title slug ver } } }"}'
```

## HTTP Status Codes

| Status Code | Meaning | Description |
|---|---|---|
| `200 OK` | Success | Request succeeded |
| `201 Created` | Created | Resource successfully created |
| `400 Bad Request` | Bad Request | Invalid inputs or malformed body |
| `401 Unauthorized` | Unauthorized | Bearer token required in HTTP Header |
| `403 Forbidden` | Forbidden | Insufficient permissions for operation |
| `404 Not Found` | Not Found | Requested slug or resource not found |
| `429 Too Many Requests` | Rate limited | Too many requests; retry later |
| `500 Internal Error` | Internal Server Error | Server-side exception |
